# THE MYTH — 통합 세계관 아카이브 및 창작 워크스테이션 구축

## 최상위 임무

너는 창작 프로젝트 《The Myth》를 위한 전용 Site의 설계 및 구현 담당 개발자다.

이번 작업의 목표는 《The Myth》의 전체 세계관과 본편·외전·사상집을 하나의 시스템에서 관리하고 편집할 수 있는 **실제 작동하는 웹 기반 창작 워크스테이션**을 구축하는 것이다.

기획서나 UI 목업만 제출하지 말고, 데이터 저장·편집·검색·연결·집필 기능이 실제로 작동하도록 구현하라.

이 프로젝트는 기존 UNIFIED THINK TANK, 성경 시공간 아틀라스, 메모 탐색기, 손로운 마법 수학 지도 및 다른 Site와 별개의 독립 프로젝트로 유지한다.

기존 프로젝트의 데이터나 코드를 임의로 변경하지 마라.

---

## 1. 전체 사이트 구성

사이트 이름은 다음과 같다.

**THE MYTH**

최상위 탭은 정확히 두 개로 구성한다.

- **본편**
- **외전+사상집**

세계관 아카이브, 통합 연대기, 우주 공간, 인물·집단·사건·설정 관리 등은 모두 '본편' 탭의 하위 기능이다.

외전 단편과 캐릭터별 철학 서적 및 사상 아카이브는 '외전+사상집' 탭에서 관리한다.

상단에 별도의 대형 탭을 추가하지 마라. 필요하다면 하위 메뉴·필터·패널을 사용한다.

두 탭은 하나의 통합 세계관 데이터베이스를 공유한다.

## 2. 본편 — 세대와 타이틀의 계층

《The Myth》는 전체 세계관을 관통하는 세 가지 세대로 구성된다.

- 1세대: Earth
- 2세대: Universe
- 3세대: 명칭 및 세부 구성 추후 확정

각 세대 아래에는 여러 개의 독립된 작품 타이틀이 배치된다.

기존 구상에 등장하는 1세대의 위버멘쉬, 마몬, 아나키, 랑데부 등을 등록 가능한 타이틀로 지원한다.

확정되지 않은 다른 타이틀이나 3세대의 세부 설정은 임의로 창작하여 채우지 마라.

사용자가 세대와 타이틀을 자유롭게 생성·수정·이동·삭제할 수 있어야 한다.

각 타이틀에는 제목, 설명, 작품 상태, 관련 인물, 집단, 사건, 공간, 설정, 시간 범위 등을 연결한다.

특히 **타이틀별로 세계관 자료를 중복 복제하지 않는다.**

하나의 인물이 여러 타이틀에 등장할 수 있고, 동일한 사건이나 행성이 여러 작품에서 참조될 수 있어야 한다.

### 본편 탐색 인터페이스

본편을 열면 세대 및 타이틀을 선택할 수 있고, 선택된 타이틀에 해당하는 자료를 탐색할 수 있게 한다.

동시에 모든 세대와 작품을 통합 검색할 수 있는 전체 아카이브 접근 기능도 제공한다.

타이틀 중심 탐색과 전체 아카이브 중심 탐색을 모두 지원하되, 두 화면은 동일한 데이터 원본을 사용해야 한다.

## 3. 세계관 통합 아카이브

본편에는 다음 데이터 유형을 독립적인 객체로 관리하는 아카이브를 구현한다.

- 인물
- 집단 및 조직
- 사건
- 우주 공간
- 행성 및 문명
- 사상력·에너지·무술 등 세계관 설정
- 기타 사용자가 직접 정의하는 분류 및 설정 항목

모든 객체에는 고유 ID를 부여한다.

기본 관리 기능은 다음과 같다.

- 새로운 객체 추가
- 기존 객체 내용 수정
- 객체 삭제 및 복원
- 여러 객체의 그룹화
- 그룹 생성·수정·삭제
- 상위·하위 그룹 구성
- 그룹 간 객체 이동
- 한 객체의 여러 그룹 동시 소속
- 객체 분할 및 병합
- 객체 정렬 및 순서 변경
- 객체 사이의 관계 설정
- 통합 검색 및 조건별 필터링

기존 《페르소나의 탑》 설정 Site에서 사용했던 것처럼 사용자가 인물과 사건을 직접 편집하고 그룹을 구성할 수 있는 관리 방식을 기본 경험으로 삼는다.

객체를 그룹에서 제거하는 행위와 데이터베이스에서 완전히 삭제하는 행위는 명확히 구분한다.

다른 작품이 참조하고 있는 객체를 삭제할 때는 영향을 받는 연결을 표시하고, 의도하지 않은 연쇄 삭제를 방지한다.

분할과 병합 시에도 기존 참조 관계가 잘못 연결되거나 사라지지 않도록 처리한다.

## 4. 인물 관리 — 출신 행성과 통합 타임라인

《The Myth》의 등장인물은 여러 작품에서 반복적으로 등장하며, 서로 다른 시대에 다른 역할을 맡을 수 있다.

따라서 한 인물이 작품마다 별도 객체로 저장되어서는 안 된다.

모든 인물은 **하나의 전역 인물 객체**로 관리한다.

### 기본 정체성

인물별로 다음 정보를 관리한다.

- 이름 및 별칭
- 출신 행성
- 출신 문명·종족
- 기본 프로필
- 관련 인물
- 기타 사용자 정의 정보

특히 출신 행성은 인물의 기본 아이덴티티로 사용한다.

현재 거주 행성, 활동지, 정치적 소속, 소속 집단은 출신 행성과 별도로 저장한다.

### 시간에 따라 달라지는 정보

- 나이 및 외형
- 소속 집단과 직위
- 현재 활동 행성
- 능력과 무술
- 사상과 가치관
- 생존 및 활동 상태
- 작품별 등장 여부와 역할

각 속성은 적용되는 시점을 기록할 수 있어야 한다.

한 인물이 동시에 여러 조직에 속할 수도 있다.

집단 소속은 시작·종료 시점이 있는 관계 데이터로 관리하며, 과거 기록을 덮어쓰지 않는다.

특정 타이틀에 등장하지 않는다는 이유로 그 시대의 존재나 집단 소속이 제거되어서는 안 된다.

인물 상세 페이지에서는 하나의 타임라인에서 과거와 미래의 모든 변화를 탐색할 수 있도록 한다.

## 5. 통합 연대기

《The Myth》에는 전체 우주를 관통하는 하나의 공통 시간축이 존재한다.

세계관에는 '우주 절대 연도'라는 기년법이 있지만, 정확한 연도 수치는 아직 결정되지 않았다.

따라서 숫자 연도가 없어도 사건과 인물의 변화를 기록할 수 있어야 한다.

### 필수 시간 표현

- 확정된 절대 연도
- 미확정 연도
- 특정 사건 이전 또는 이후
- 특정 기간
- 사건 간 선후 관계
- 타이틀별 시작·종료 시점
- 서로 중첩되는 작품의 시간 범위

**각 타이틀의 시간 범위는 서로 중첩될 수 있다.**

세대와 타이틀의 목록 순서가 반드시 세계관 내부의 실제 연대순을 의미하지는 않는다.

정확한 연도가 정해지기 전에도 사용자가 사건의 순서를 직접 조정할 수 있게 구현한다.

연도 미확정 기록을 강제로 가짜 날짜에 배치하지 마라.

### 타임라인에서 연결할 객체

- 인물의 변화
- 집단의 창설·해체·구성원 변화
- 사건의 발생과 결과
- 행성의 정치적 상태
- 문명과 통치 관계의 변화
- 능력과 무술의 등장 및 발전
- 타이틀별 서사 기간

사용자가 특정 시점 또는 타이틀을 선택하면 해당 시점에서 유효한 인물 상태, 집단 소속, 행성의 통치 관계 등을 확인할 수 있어야 한다.

시점을 확정할 수 없는 정보는 미확정 상태로 표시한다.

동시에 성립할 수 없는 상태 기록이 발견되면 사용자에게 충돌을 표시하되, 데이터를 임의로 수정하거나 삭제하지 마라.

## 6. 우주 공간 아카이브

공간 관리는 《The Myth》 사이트의 핵심 기능이다.

세계관은 하나의 물리적 우주를 배경으로 한다.

그 안에 여러 은하가 존재하며, 각 은하에는 대략 3~4개의 문명 행성이 존재한다.

이는 세계관의 일반적인 규모이지 데이터베이스의 최대 개수 제한이 아니다.

### 공간 계층

다음과 같은 탐색 구조를 기본으로 구현한다.

우주 → 은하 → 항성계 → 행성 → 대륙 → 국가·지역 → 도시 → 개별 장소

작품에 필요한 경우 중간 단계를 생략하거나 추가할 수 있게 한다.

사용자는 공간 객체를 자유롭게 생성·삭제·이동·편집할 수 있어야 한다.

### 공간 객체의 정보

은하와 행성에는 다음 정보를 연결한다.

- 명칭과 설명
- 상위 공간 및 하위 공간
- 물리적 환경과 지리
- 문명과 종족
- 정치적 세력 및 통치 관계
- 주요 집단과 인물
- 고유 문화와 무술
- 관련 사건
- 관련 타이틀
- 시대별 변화

물리적 공간과 정치적·문명적 소속은 별도의 데이터로 관리한다.

예를 들어 행성 자체는 같은 객체로 유지하면서 해당 행성을 지배하는 문명이나 국가가 시간에 따라 달라질 수 있어야 한다.

### 갤럭시 마스터

《The Myth》의 은하에는 일반적으로 '갤럭시 마스터'라 불리는 지배적 문명이 하나씩 존재한다.

갤럭시 마스터가 없는 은하는 드문 예외다.

갤럭시 마스터의 주된 성격은 정복과 착취보다 은하 전체의 통치, 조율 및 질서 유지에 있다.

일반 시민은 은하 차원의 정치적 질서나 갤럭시 마스터의 존재를 거의 알지 못할 수도 있다.

이를 단순한 정복 제국이나 반드시 공개된 중앙정부로 해석하여 임의의 설정을 추가하지 마라.

각 은하에서 갤럭시 마스터의 존재 여부, 관련 문명, 지배 또는 조율 관계, 적용 시기 등을 기록할 수 있도록 구현한다.

구체적인 통치 제도와 권한은 아직 미확정이므로 사용자가 추후 입력할 수 있도록 비워둔다.

### 공간 탐색 기능

은하를 선택하면 그 은하에 속하는 문명 행성과 관련 집단을 볼 수 있어야 한다.

행성을 선택하면 고유 문명, 종족, 인물, 사건, 무술, 정치적 상태를 탐색할 수 있어야 한다.

가능하면 계층형 우주 탐색 화면과 관계 시각화를 제공한다.

실제 천체 좌표나 상대적 위치가 확정되지 않은 경우 임의의 천문학적 위치를 사실처럼 표시하지 마라.

좌표와 지도가 없더라도 계층 및 관계 탐색이 정상적으로 작동해야 한다.

## 7. 세계관 설정 — 사상력·에너지·무술

《The Myth》의 초인들은 사상력과 에너지를 다룬다.

또한 행성별로 고유한 무술이나 능력 운용 방식이 존재한다.

이 항목들을 단순 메모가 아니라 독립적으로 분류하고 서로 연결할 수 있는 설정 객체로 구현한다.

각 설정에는 다음 정보를 관리한다.

- 이름
- 분류
- 정의 및 설명
- 관련 원리
- 사용 조건
- 관련 행성·문명
- 사용자 또는 전승 집단
- 관련 인물
- 관련 사건
- 역사적 변화
- 관련된 다른 설정

세계관의 실제 능력 체계와 사상력·에너지의 관계는 사용자가 직접 확정한다.

AI가 임의로 능력 법칙이나 상하관계를 만들어 확정 설정으로 등록하지 마라.

## 8. 외전+사상집 — 외전 창작실

두 번째 최상위 탭에는 외전 단편을 관리하고 실제로 집필하는 기능을 구현한다.

각 단편은 독립적인 작품 객체로 관리한다.

필요한 기능은 다음과 같다.

- 단편 작품 추가·수정·삭제
- 제목과 소개
- 집필 상태
- 관련 본편 타이틀
- 배경 시간대
- 주요 등장인물
- 관련 행성 및 사건
- 작품별 구성 메모
- 본문 집필 및 편집
- 자동 임시 저장
- 원고 버전 관리
- 텍스트 및 Markdown 내보내기

외전에서도 본편의 통합 인물·사건·공간 데이터를 참조한다.

외전에서 새로운 설정이 작성되더라도 사용자의 명시적인 확정 없이 본편의 공통 세계관 데이터를 자동 변경하지 않는다.

외전의 설정은 초안·확정·비정사 또는 미정과 같은 상태를 구분할 수 있도록 설계한다.

## 9. 외전+사상집 — 캐릭터별 사상집 집필실

사상집은 《The Myth》의 등장인물이 직접 집필했다고 가정하는 철학 서적 또는 자기계발서를 의미한다.

이 패널은 단순한 인물 설정 메모가 아니라 실제 서적 원고를 작성하는 작업 공간이어야 한다.

### 서적 관리

각 캐릭터는 여러 권의 서적을 저술할 수 있다.

서적별로 다음 정보를 관리한다.

- 제목
- 저자 캐릭터
- 서적 유형
- 집필 상태
- 세계관 내 집필 시점
- 소개 및 기획 의도
- 목차
- 장·절별 원고
- 개정 이력
- 관련 사상과 철학적 주장

본문은 편집 가능한 텍스트 에디터로 제공한다.

장과 절은 자유롭게 추가·삭제·순서 변경할 수 있어야 한다.

서적 전체 또는 개별 장을 파일로 내보낼 수 있어야 한다.

### 사상 아카이브

사상집 집필을 지원하기 위해 별도의 사상·철학 자료 관리 기능을 두 번째 최상위 탭 내부에 구현한다.

사상 아카이브에서는 다음 정보를 관리한다.

- 사상의 이름
- 정의
- 중심 주장
- 논거와 반론
- 관련 사상가
- 계승·발전·비판 관계
- 다른 사상과의 관계
- 해당 사상을 채택하거나 비판하는 캐릭터
- 관련 서적 및 원고

하나의 사상에는 여러 사상가가 연결될 수 있어야 한다.

사상가와의 관계에는 창시·계승·발전·비판·수용·거부 등 서로 다른 유형을 지정할 수 있어야 한다.

실제 역사 속 사상가와 《The Myth》의 가상 사상가는 구분할 수 있는 구조로 만든다. 다만 현실 철학자 자료의 수집 범위는 아직 확정되지 않았으므로 임의로 대량 등록하지 않는다.

특히 **사상가의 주장과 세계관의 객관적 설정은 구분한다.**

캐릭터가 자기 책에서 주장한 철학적 명제가 반드시 세계관의 진실로 확정되어서는 안 된다.

가능하면 인물의 사상적 변화도 통합 연대기와 연결한다.

## 10. 객체 간 관계 및 데이터 무결성

이 사이트의 핵심은 모든 정보가 서로 연결되면서도 중복 저장되지 않는 것이다.

다음 관계를 우선 지원하라.

- 인물 ↔ 타이틀
- 인물 ↔ 출신 행성
- 인물 ↔ 소속 집단
- 인물 ↔ 사건
- 인물 ↔ 인물
- 집단 ↔ 문명
- 문명 ↔ 은하·행성
- 사건 ↔ 시간·공간
- 능력·무술 ↔ 인물·문명
- 사상 ↔ 사상가
- 사상 ↔ 서적
- 서적 ↔ 저자 캐릭터
- 단편 ↔ 본편 세계관 자료

객체의 연결 관계에는 필요할 경우 시점과 관계 유형을 함께 저장한다.

인물 이름이나 집단 이름이 변경되어도 기존 연결이 유지되도록 내부 고유 ID를 사용한다.

중복 객체 병합은 사용자가 명시적으로 실행해야 하며, 충돌하는 필드와 연결 관계를 확인할 수 있도록 한다.

## 11. 사용자 인터페이스

전체 디자인은 창작자가 장시간 사용하는 전문적인 작업 환경을 지향한다.

과도하게 장식적인 카드나 복잡한 대시보드보다 탐색과 편집 효율을 우선한다.

### 기본 레이아웃

상단:
- THE MYTH 프로젝트 이름
- 본편 / 외전+사상집 전환
- 검색 및 저장 상태

본편 내부:
- 세대·타이틀 선택
- 인물·집단·사건·공간·설정·연대기 탐색
- 목록 및 그룹 관리
- 상세 정보 편집
- 관련 객체 연결
- 시점별 상태 확인

외전+사상집 내부:
- 외전 및 사상집 작업 유형 선택
- 작품 또는 서적 목록
- 목차 및 구성 요소
- 본문 편집
- 관련 세계관 자료 참조

세부 메뉴를 전환하더라도 사용자가 작업 중이던 내용을 불필요하게 초기화하지 마라.

### 편집 안정성

다음 조건을 반드시 만족해야 한다.

- 편집창 바깥을 실수로 클릭하더라도 작성 중인 내용이 사라지지 않을 것
- 자동 임시 저장 또는 변경 사항 보호 기능을 제공할 것
- 미저장 변경 사항이 있으면 이를 명확히 표시할 것
- 삭제와 병합 같은 위험 작업에는 확인 절차를 둘 것
- 수정 이력 또는 이전 버전 복원 기능을 제공할 것
- 목록과 상세 화면을 오가더라도 검색·필터 상태를 최대한 유지할 것

데스크톱 환경을 우선하되 모바일 화면에서도 탐색과 기본 편집이 가능하게 한다.

## 12. 실제 데이터 저장 및 백업

단순한 프런트엔드 시연 화면으로 구현하지 마라.

인물이나 작품을 추가한 뒤 사이트를 새로고침하거나 다시 실행하더라도 실제 데이터가 보존되어야 한다.

현재 개발 환경에 적합한 지속형 데이터 저장 방식을 선택하라.

데이터베이스에서는 전역 객체와 작품별 참조, 시점별 상태, 그룹 관계, 문서 원고를 구분하여 관리한다.

다음 기능을 포함한다.

- 데이터베이스 스키마 및 마이그레이션
- 영속 저장
- 데이터 내보내기
- 백업 데이터 복원
- 실수로 삭제한 객체 복구
- 원고 버전 관리

사용자 데이터와 개발 테스트 데이터를 구분한다.

실제 사용자 설정을 삭제하거나 덮어쓰지 마라.

## 13. 초기 데이터 정책

초기에는 이미 확인된 설정만 등록한다.

확인된 주요 구조는 다음과 같다.

- 하나의 물리적 우주
- 1·2·3세대 구분
- 각 세대 아래의 여러 작품 타이틀
- 타이틀별 중첩 가능한 연대기
- 우주 절대 연도라는 공통 기년법의 존재
- 은하별 대략 3~4개의 문명 행성
- 거의 모든 은하에 존재하는 갤럭시 마스터 문명
- 행성 출신을 기본 정체성으로 하는 인물
- 사상력·에너지·행성별 무술
- 캐릭터가 저술하는 철학서와 자기계발서
- 외전 단편 작품

구체적인 인물 이름이나 행성, 사건 및 능력 법칙이 제공되지 않았다면 임의로 창작하지 않는다.

기능 테스트가 필요한 경우 실제 설정과 분리된 테스트 데이터나 가상 fixture를 사용하고, 테스트 자료임을 명시한다.

## 14. 필수 기능 검증

구현 후 다음 시나리오를 직접 테스트하라.

### 인물

1. 인물 A를 생성하고 출신 행성을 연결한다.
2. 서로 다른 두 타이틀에 같은 인물 A를 등록한다.
3. 각 작품의 등장 역할을 다르게 설정한다.
4. 특정 시점에 소속 집단을 변경한다.
5. 다른 작품에서도 같은 인물의 변경 이력이 올바르게 표시되는지 확인한다.

### 연대기

1. 절대 연도가 없는 사건을 생성한다.
2. 사건 간 선후 관계를 지정한다.
3. 두 타이틀의 시간 범위를 중첩시킨다.
4. 해당 시점의 인물·집단 상태를 확인한다.
5. 미확정 연도가 임의의 숫자로 저장되지 않는지 확인한다.

### 공간

1. 은하를 생성한다.
2. 여러 문명 행성을 등록한다.
3. 은하에 갤럭시 마스터 문명을 연결한다.
4. 특정 행성의 통치 관계를 시간에 따라 변경한다.
5. 행성의 고유 정체성과 과거 통치 기록이 그대로 유지되는지 확인한다.

### 아카이브 편집

1. 객체를 생성·수정·삭제·복원한다.
2. 그룹을 생성하고 여러 객체를 묶는다.
3. 같은 객체를 여러 그룹에 연결한다.
4. 그룹에서 제거해도 전역 객체가 삭제되지 않는지 확인한다.
5. 분할·병합 작업 시 연결 관계가 어떻게 처리되는지 검증한다.

### 사상집 및 외전

1. 인물 A가 저술한 서적을 생성한다.
2. 여러 장과 절을 작성하고 순서를 변경한다.
3. 사상 객체를 생성해 서적과 저자를 연결한다.
4. 외전 단편을 작성하고 본편 인물을 참조한다.
5. 원고를 저장·재실행·복원·내보내기한다.
6. 외전의 미확정 설정이 본편의 확정 데이터에 자동 반영되지 않는지 확인한다.

모든 검증에서 실제 사용자 데이터가 아닌 별도 테스트 데이터를 사용한다.

## 15. 개발 및 완료 기준

먼저 현재 접근 가능한 작업 환경과 저장소를 조사하라.

이미 이 프로젝트의 소스가 존재한다면 이를 보존하고 기존 구조에서 작업을 이어간다.

새 프로젝트라면 유지보수 가능한 웹 애플리케이션 구조로 생성한다.

현재 환경의 기술 스택과 배포 제약을 확인한 뒤 적절한 구현 방법을 선택한다.

다른 프로젝트의 저장소와 배포 설정을 임의로 변경하지 마라.

**이번 작업은 기획 단계가 아니라 실제 구현 단계다.**

다음 조건을 완료 기준으로 한다.

- 두 개의 최상위 탭이 정상 동작한다.
- 인물·집단·사건·공간·설정을 실제로 등록·편집할 수 있다.
- 그룹 및 객체 관계를 관리할 수 있다.
- 중첩되는 타이틀의 통합 연대기가 작동한다.
- 인물의 출신 행성과 시대별 집단 소속을 구분한다.
- 은하와 행성, 갤럭시 마스터의 관계를 기록할 수 있다.
- 외전 및 사상집 원고를 실제로 작성·저장할 수 있다.
- 데이터가 새로고침·재실행 후에도 보존된다.
- 검색과 연결 탐색이 작동한다.
- 핵심 기능의 자동 검증과 직접 실행 검증이 완료된다.

단순히 기능을 표현하는 버튼이나 빈 패널을 배치한 것만으로 완료 처리하지 마라.

가능한 기능은 실제로 구현하고, 환경 또는 권한 때문에 구현하지 못한 항목은 구분하여 보고하라.

완료 보고에는 다음을 포함한다.

- 구현된 기능
- 구현하지 못한 기능과 원인
- 저장소·브랜치·주요 커밋
- 실행 및 접속 방법
- 테스트 항목별 PASS/FAIL
- 데이터 보존 및 백업 방법
- 다음 개선 작업에 대한 제안
