# 《시간》 외전 설정과 공통 인물 관리

이 기능은 기존 The Myth의 외전 원고와 전역 인물 저장소를 확장한다. 본편 작품(`title`)과 A–Z 명예 칭호는 서로 다른 기록이며, 새 테이블·사이트·접근 권한·D1/R2 바인딩을 만들지 않는다.

## 사용 방법

1. **외전+사상집 → 외전 창작실**에서 외전을 선택하고 **설정 관리**를 연다. 원고 집필 화면은 별도로 유지된다.
2. 설정 관리의 작품 개요, 인물, 사건·관계, 배경·규칙, 사상·담론, 검토·출처에서 자료를 편집한다. 확정 상태와 공개 범위는 별개로 지정한다.
3. 인물은 칭호 알파벳 순서로 표시하며 한국어 이름·영문명·별칭·칭호·직역으로 검색한다. 본편 인물과 동일성이 확인되지 않으면 외전 인물로 유지한다.
4. **본편 인물 연결**에서 후보의 설명과 등장 작품을 비교하고 공통 필드의 충돌마다 사용할 값을 선택한다. 같은 이름·알파벳이라는 이유로 자동 연결하지 않는다.
5. **공통 정보 수정**은 연결된 작품들이 참조하는 이름·영문명·별칭·기본 설명을 수정한다. **이 작품에서만 수정**은 작품별 재정의와 그 이유를 저장한다. 공통값을 다시 사용하면 해당 재정의만 제거한다.
6. **공통 정보에 반영**에서는 선택한 작품별 필드의 변경 전후와 영향 작품을 확인한다. 다른 작품의 재정의값은 유지된다.
7. 연결 해제는 현재 외전에서 보던 유효한 정보를 작품별 값으로 보존한다. 본편 원본 인물, 다른 작품, 기존 사건·관계·사상의 대상 ID는 삭제하거나 이동하지 않는다.

## 입력과 보존

`GET /api/works/time`으로 현재 상태와 저장 번호를 확인하고, 명시적으로 `POST /api/works/time/import`를 실행한다. 읽기·서버 기동·배포만으로 설정을 자동 입력하지 않는다. 외전 창작실의 설정 적용 버튼도 같은 API를 사용한다.

최신 사용자 확정 설정의 초기 구성은 외전 1편, 인물 27명, 명예 칭호 26개와 연결 27개, 사건·상황·목표 8개, 핵심 인물 관계 6개, 사건 참여 연결 11개, 사상 4개, 세계관 규칙 5개, 검토 항목 12개다. 테르노스와 테라, Knight와 Night는 각각 별개의 고유 인물이다. 테라의 T 취득 시점·현직 여부, 인물별 초능력, 비공개 증명 방법을 창작하지 않는다. 정확한 세대·시대·지역은 미정이며 3세대에 자동 배치하지 않는다.

각 입력 기록은 안정적인 입력 식별자와 최초 입력값을 보관한다. 재실행 시 같은 기록을 재사용하고, 사용자 편집이 최초 입력값과 다르면 보존하여 충돌로 보고한다. 삭제 기록을 자동 복원하지 않는다. 작품명을 변경해도 ID와 관계는 유지된다. 실행 전 백업과 실행 후 입력 영수증은 작업 공간에 보관하고 소스 저장소에 운영 데이터나 자격증명을 넣지 않는다.

## 원문 확인 범위

2026-11-18 기준 지정된 Library 기획 문서와 담론 목록을 읽을 수 있는 직접 도구나 허가된 Page 파일 참조를 확보하지 못했다. 따라서 14개 범주·120개 담론의 번호·본문·출처·검토 상태는 **미확인**이며 가짜 항목을 만들지 않는다. 기존 GPT 제안을 사용자 확정 설정으로 간주하지 않는다. 이후 원문을 확보하면 기존 기록과 최신 사용자 편집을 비교하여 추가 반영해야 한다.

## 저장 계약과 복구

외전 인물은 기존 `entities`의 인물과 `documents`의 외전 사이 `work_appearance`로 연결한다. 본편 동일인 연결은 작품 범위의 `identity_link`로 관리한다. 단순 연결은 중복 인물 병합과 다르며, 별도의 병합 동작을 자동 실행하지 않는다.

공통·작품별·동일인 변경은 전역 저장 번호와 비교 대상 기록들의 revision을 확인한 뒤 기존 D1 일괄 저장으로 반영한다. 충돌한 초안은 보존하고 최신값과 비교한 뒤 명시적으로 다시 적용한다. 백업은 기존 전체 JSON에 새 등장·재정의·연결·칭호를 포함하며, JS와 Python 복원 경로 모두 이를 검증한다. 운영 복원은 별도 승인 없이 실행하지 않는다.

호스팅은 기존 owner-private Sites의 공식 소스 저장·버전 배포 절차를 사용한다. 설정 입력은 별도의 실제 API 쓰기이므로 배포 성공만으로 운영 데이터 입력 완료라고 보고하지 않는다. 네트워크·인증·브라우저 장애가 있으면 해당 범위를 정확히 기록한다.
