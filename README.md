# THE MYTH

《The Myth》를 위한 독립적인 세계관 아카이브와 집필 워크스테이션입니다. 본편과 외전+사상집이 같은 전역 객체를 참조하고, 데이터와 원고는 서버의 SQLite 파일에 저장합니다.

ChatGPT Sites 연결과 후속 개발은 [docs/SITES_CONNECTION.md](docs/SITES_CONNECTION.md)를 읽으세요. 기존 Python 구현은 보존되어 있으며, 같은 화면과 데이터 계약을 Sites의 D1·R2 저장소에 연결하는 호스팅 어댑터를 추가했습니다. 기존 비공개 사용자 백업의 실제 이전은 아직 대기 중입니다. 이전 Codex 인계 기록은 [WORK_HANDOFF.md](WORK_HANDOFF.md)에 남깁니다.

## 실행

Python 3.12 이상이 필요합니다. 프런트엔드 빌드나 Node 패키지 설치는 필요하지 않습니다.

```bash
cd /workspace/TheMyth
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
bash scripts/run.sh
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 기본 서버는 로컬 접속만 허용하도록 바인딩됩니다. 원격 머신에서는 SSH 포트 포워딩 등 신뢰할 수 있는 접속 경로를 사용하세요. 이 앱은 개인 창작 작업용이며 사용자 인증·권한 관리 기능을 포함하지 않습니다. 인증 게이트웨이 없이 공용 인터넷에 노출하지 마세요.

서버 실행 설정:

| 환경 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `MYTH_DB_PATH` | `data/myth.sqlite3` | 영속 데이터베이스 경로 |
| `MYTH_HOST` | `127.0.0.1` | 서버 바인딩 주소 |
| `MYTH_PORT` | `8000` | 서버 포트 |

이미 준비된 클라우드 작업에서는 기존 `/workspace/TheMyth` 체크아웃을 사용합니다. 별도 Git worktree를 만들 필요가 없습니다. 서비스 프로세스는 환경 재시작 후 `bash scripts/run.sh`로 다시 시작합니다.

## 데이터 원칙

- 인물·행성·사건·설정은 고유 ID를 가진 전역 객체입니다. 여러 작품에 연결해도 복제하지 않습니다.
- 인물의 출신 행성과 시간에 따른 활동지·소속은 별도로 기록합니다.
- 미확정 시간은 실제 미확정 값으로 보존합니다. 우주 절대 연도를 임의로 채우지 않습니다.
- 물리적 공간 계층과 통치·문명·갤럭시 마스터 관계는 분리합니다.
- 외전·사상집 원고의 내용과 정사 상태는 세계관 객체를 자동 변경하지 않습니다.
- 초기 데이터에는 요청에서 확인된 세대·구상 타이틀·우주 구조만 포함합니다. 실제 인물이나 행성·사건은 만들어 넣지 않습니다.

원본 요구사항은 [docs/PRODUCT_REQUIREMENTS.md](docs/PRODUCT_REQUIREMENTS.md)에 보존했습니다.

## 검증

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
bash scripts/check.sh
```

테스트는 임시 디렉터리의 별도 SQLite 데이터베이스를 사용합니다. `data/`의 사용자 데이터를 테스트 fixture로 사용하지 않습니다. 검증 결과와 구현 범위는 [docs/VALIDATION.md](docs/VALIDATION.md)를 확인하세요.

실제 브라우저 검증은 `.venv/bin/python scripts/browser_smoke.py`로 실행합니다. 시스템 Chromium이 없으면 `CHROMIUM_PATH`를 지정하거나 `.venv/bin/python -m playwright install chromium`으로 설치하세요. 저장 모델과 시간 표현은 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)에 설명되어 있습니다.

## 사용 흐름

1. 본편의 **세대·타이틀**에서 작품을 관리합니다. 세대는 표시 순서와 고유 번호를 따로 관리합니다. 작품 시간 표현을 기간으로 지정하면 다른 타이틀과 중첩할 수 있습니다.
2. **우주 공간**에서 공간과 행성을 만들고 상위 물리적 공간을 지정합니다. 문명은 **집단·문명**에서 별도로 등록합니다. 갤럭시 마스터·통치·조율은 관계 유형으로 연결하고 적용 시기를 입력합니다.
3. **인물**의 출신 행성을 지정합니다. 작품 등장(`appearance`), 집단 소속(`membership`) 등을 관계로 연결하고 역할·직위·시작·종료를 기록합니다. 과거 소속 기록을 수정해 덮는 대신 새 관계를 추가하세요.
4. 기본 속성 외의 변화는 **시대별 변화**에서 기록합니다. **통합 연대기**에서 연도 또는 타이틀을 선택해 유효 상태·소속·불확실한 기록과 충돌을 조회합니다.
5. **그룹 관리**는 자료를 복제하지 않고 여러 그룹에 연결합니다. 그룹 제거와 전역 삭제는 별도 동작입니다. 분할과 병합은 각 자료 상세에서 실행하며 원본과 참조를 보존합니다.
6. **외전+사상집**에서 작품 또는 서적을 만들고 본문과 장·절을 집필합니다. 원고는 자동 저장하고, 장·절별 순서 변경·이전 버전 복원·내보내기를 지원합니다. 사상·사상가를 독립 등록하고 저술·창시·수용·비판 등의 관계를 연결하세요.
7. 원고나 객체의 미저장 초안이 있으면 표시합니다. 다른 창과 충돌했다면 서버 내용 사용 또는 내 초안으로 다시 저장을 명시적으로 선택할 수 있습니다. 상단 통합 검색은 장·절 본문도 검색합니다.

## 데이터 보존과 백업

프로그램 종료나 새로고침은 SQLite 데이터를 지우지 않습니다. 기본 저장 위치인 `data/`는 Git에서 제외되어 있습니다. 저장소를 복사하거나 배포할 때 데이터 파일은 별도로 보관해야 합니다.

화면의 백업 내보내기 기능은 객체·연결·시점별 상태·그룹·원고·버전을 JSON으로 내려받습니다. 복원은 파일을 선택해 실행합니다. 기존 데이터가 있다면 ID 충돌을 확인하며, 전체 교체는 명시적인 확인을 거치는 별도 작업입니다. 교체 전 자동 보관 파일도 백업하되, 정기적으로 다른 저장장치에 백업을 복사하세요.

실행 중인 SQLite 파일 하나만 복사하면 WAL의 최근 변경이 빠질 수 있습니다. 앱의 JSON 내보내기를 사용하거나, SQLite의 온라인 backup API를 사용하세요.

```python
import sqlite3

with sqlite3.connect('data/myth.sqlite3') as source:
    with sqlite3.connect('myth-snapshot.sqlite3') as target:
        source.backup(target)
```

삭제한 객체는 휴지통에서 복원할 수 있습니다. 객체 삭제는 참조를 연쇄 삭제하지 않습니다. 원고의 이전 버전 복원은 현재 원고를 덮기 전에 별도 이력을 남기는 방식입니다. 브라우저의 임시 편집 복구 데이터는 서버 백업을 대신하지 않습니다.
